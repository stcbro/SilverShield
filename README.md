# 银盾 SilverShield

> 帮长辈自动跳过开屏广告与烦人弹窗 —— 一款基于 Android 无障碍服务的轻量工具。

银盾只做一件事：**替用户点一下界面上本来就有的「跳过 / 关闭」按钮**。它不破解、不屏蔽、不删除任何广告，也不注入、不修改第三方应用，更不收集个人隐私。

---

## 为什么要做这个

对年轻人来说，开屏广告点一下「跳过」就过去了；对长辈来说，那 5 秒的等待、5 秒后仍在跳转的诱导页面、以及藏在角落里的「×」，往往意味着误触、误装、误付费。

银盾的定位不是对抗厂商，而是给老人**补上那一只手**：

- 开屏广告出现时，替他们点「跳过」；
- 弹窗出现时，替他们点「关闭」；
- 拨号、支付、相机等关键界面**一律不动作**，绝不误触。

治本仍然要靠法规与行业自律。银盾只是过渡期的一根拐杖。

## 功能一览

| 功能 | 说明 |
|---|---|
| **自动跳过** | 识别开屏广告、应用内弹窗的「跳过 / 关闭」控件并自动点击，内置 333 条规则覆盖主流应用 |
| **两级匹配** | 先按资源 ID / 文案精准命中规则库，再用「跳过 / 关闭 / 跳过广告」等关键词兜底扫描 |
| **规则热更新** | 启动时与每日后台自动拉取最新规则并合并，用户无需任何手动操作 |
| **防误伤保护** | 拨号、通话、相机、支付、输入法等界面完全跳过，不做任何点击 |
| **拦截统计** | 记录每次拦截并按应用排行，可一键分享给子女，让家人看见它确实在工作 |
| **大字界面** | 全应用 18–34sp 大字号、高对比度配色，为适老化设计 |
| **语音播报** | 可选开启，用系统 TTS 播报当前守护状态 |
| **版本更新** | 联网检查更新，由维护者决定何时推送，避免频繁打扰 |

## 工作原理

```
AccessibilityService 接收窗口变化事件
        │
        ├─ 紧急保护判断 ──► 拨号 / 支付 / 相机等界面 → 直接返回
        │
        ├─ 取当前前台应用包名 → String.hashCode() → 查规则库
        │        │
        │        ├─ popup_rules：按资源 ID 或文案定位「关闭」按钮 → 点击
        │        └─ keywords：按「跳过 / 关闭广告」等关键词遍历节点 → 点击
        │
        └─ 兜底：在疑似广告窗口中寻找右上角关闭控件
```

点击优先使用 `dispatchGesture` 派发**真实触摸事件**（可绕过只响应 `OnTouchListener` 的广告按钮），失败时回退 `ACTION_CLICK`。同一应用内做 500ms 去抖，避免重复点击。

规则以包名的 Java `String.hashCode()` 为 key，单条格式：

```json
{
  "-173313837": "{\"popup_rules\":[{\"id\":\"+立即升级\",\"action\":\"+以后再说\"}],\"keywords\":[\"跳过\",\"关闭广告\"],\"package_name\":\"com.qihoo360.mobilesafe\"}"
}
```

`popup_rules` 中 `id` 为触发条件，`action` 为点击目标；前缀规则：`+` 开头表示前缀匹配、`-` 结尾表示后缀匹配、`=` 开头表示完全相等，缺省为包含匹配。

## 安装与使用

### 安装

从 [Releases](https://gitee.com/stcbro/SilverShield/releases) 下载最新 APK 安装即可，支持 Android 7.0（API 24）及以上。

> 覆盖安装后，系统会自动关闭无障碍服务，**需要到「设置 → 无障碍 → 银盾」重新开启一次**。

### 开启守护

1. 打开银盾，点击首页的「设置」卡片 → 「开启无障碍服务」；
2. 在系统无障碍列表中找到「银盾」，打开开关；
3. 返回银盾，首页状态卡片显示绿色「守护中」即生效；
4. 建议同时完成「后台保活设置」，避免被系统清理。

### 权限说明

| 权限 | 用途 |
|---|---|
| 无障碍服务 | 读取窗口内容、执行点击 —— 核心功能 |
| 通知 | 显示守护状态与开关快捷方式 |
| 网络 | 拉取规则更新与版本信息 |
| 安装未知应用 | 应用内升级时唤起安装器 |
| 查询已安装应用 | 统计页显示应用中文名称 |
| 悬浮窗 | 全屏提示居中显示（未授予时自动降级为普通 Toast） |

## 自行编译

环境：JDK 17+、Android SDK 34、Gradle 8.2（工程内已含 wrapper）。

```bash
git clone https://gitee.com/stcbro/SilverShield.git
cd SilverShield
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

用 Android Studio 打开工程根目录同样可以直接 Run。

## 规则维护

规则库分为两部分，由脚本合并生成最终文件：

```bash
node tools/merge_rules.js
# 输入：tools/b_layer.json（老人专属规则）+ 社区规则
# 输出：app/src/main/assets/AllRules.json
```

修改后的 `AllRules.json` 推送到仓库即对全体用户生效（客户端下次联网自动拉取）。规则编写规范见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 版本与发布

工程根目录有两个元数据文件，职责严格分开：

| 文件 | 作用 | 何时更新 |
|---|---|---|
| `version.json` | 记录当前最新构建（版本号、APK 地址、更新说明） | **每次发布新版本** |
| `update.json` | 用户端更新推送指针 | **仅在决定推送给用户时** |

客户端优先读取 `update.json`，读不到才回退 `version.json`。这样做的好处是：日常发版只是归档，不会打扰用户；只有维护者确认某个版本足够稳定时，才更新 `update.json` 把它推给所有用户。

发布步骤：

1. 递增 `app/build.gradle` 中的 `versionCode` 与 `versionName`；
2. 同步更新 `version.json`；
3. 构建 APK，上传至 Gitee Releases；
4. 如需推送用户更新，再更新 `update.json` 并提交。

详见 [部署指南.md](部署指南.md)。
